能力清单 · 数据流（设计稿）

N1–N4 四个待补能力的契约。六节固定；字段名为建议值。

status: draft · 设计稿 · 供审查

1接口约定 建议

N1 · pi.session.getModel()

pi.session.getModel(): Promise<{
  modelKey: string | null      // `provider/model`
  thinkingLevel: string | null
  providerId?: string
  modelId?: string
}>

权限：session.read（只读，不抬权）。与 session:modelChanged 成对：事件推变更，本方法取快照。

N2 · session:usageUpdated（事件）

// pi.events.on("session:usageUpdated", handler)
{
  sessionId: string
  turnId: string
  usage: {
    inputTokens: number
    outputTokens: number
    cacheReadTokens?: number
    cacheWriteTokens?: number
    reasoningTokens?: number
    totalTokens?: number
    toolCalls?: number
    pluginToolUsage?: number
  }
  modelKey?: string
  endedAt?: number
}

替代方案：给已有 session:turnEnded 增加 usage 字段（改动更小，事件数不增）。

N3 · pi.session.getContext()

pi.session.getContext(input?: {
  sessionId?: string     // 缺省 = 当前会话
  scope?: "all" | "sinceCompaction"
}): Promise<{
  sessionId: string
  system?: string
  messages: Array<{
    id: string
    role: "user" | "assistant" | "system" | "tool"
    text: string
    createdAt?: number
  }>
  usageEstimate: { tokens: number; truncated: boolean }
  modelKey?: string
}>

权限：新开 session.context.read（high，装时确认）——比 session.read 更宽，能读正文。

N4 · pi.session.applyCompaction()

pi.session.applyCompaction(input: {
  sessionId: string
  summary: string                    // 用户可见的摘要正文
  retainedMessageIds?: string[]      // 保留的消息；缺省 = 只留摘要
  reason?: string
}): Promise<{
  ok: boolean
  compactionId: string
  tokensBefore: number
  tokensAfter: number
}>

权限：新开 session.compact.write（high，装时确认 + 界面可见）。

2数据怎么走 建议

能力方向路径
N1拉取插件 → session RPC → host-core 会话态
N2推送endTurn 落库后 → 事件总线 → pi.events
N3拉取插件 → session RPC → 消息表 / 压缩记录
N4写入插件提交摘要 → 宿主校验并应用 → 写 ContextCompactionRecord → 广播 session:compacted
DIY 压缩时序：before_compact 拦截（可选）→ getContext 读 → 插件自算摘要 → applyCompaction 写回 → UI 显示压缩行。

3出错怎么办 建议

情况结果
无权限permission_denied，不静默
sessionId 不存在 / 已删NOT_FOUND
N3 过大truncated: true，只回窗口内
N4 与并发压缩冲突CONFLICT，要求重读再写
N4 summary 为空INVALID_PAYLOAD

4不提供什么 建议

  • 不提供 replaceMessages / 静默覆盖 message list（产品已排除）
  • N4 不静默生效：必须进压缩记录、界面可见、可审计
  • N2 不含消息正文，只含计量
  • N1 不提供改模型（改模型走会话绑定 / 受信 setModel）
  • N3 默认当前会话；跨会话读需要 sessionId + high 权限
宿主保证：权限门控、N4 审计与可见。
已接受代价：持有 session.context.read 的插件可读正文——安装审查须明示。
