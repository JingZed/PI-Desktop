输入区 · 需求

聊天输入框这一块：工具栏左右两排、打触发符弹出的列表、输入框里的记号，外加读写草稿和附件两组方法。固定件不动，其余交给插件。

status: draft · issue #545 · 对照 demo.html

范围 已定

  • 输入框工具栏：左右两排按钮里的插件位置。
  • 输入框上方弹出的列表：插件注册的触发符（如 #）触发的选择列表。
  • 输入框里面的记号：选中的东西（如 【#数据1】）在草稿里长什么样。
  • 两组方法：读写草稿（拿到输入框文字、往里写）、读写附件（拿到当前附件列表、写入附件）。
  • 不谈：发送流程本身（消息怎么入队、能不能撤回）、输入框上方的改动审阅卡、排队提示。那些是别的槽或宿主自己的事。

固定件 已定

这些控件插件碰不到：不隐藏、不替换、不排序、不在它们中间插东西（左排固定件右边、模型选择左边除外）。

槽位划分 已定

槽 / 方法位置插件能做什么
composer.left左排固定件（附件 / 模式 / 权限）的右边加自己的按钮和弹层（知识库选择、常用语……）
composer.middle右排、模型选择的左边这一段加自己的按钮；隐藏或替换宿主默认项「上下文用量」
composer.trigger打字时输入框上方弹出的列表注册一个触发符号，提供列表内容（可远程拉取）
composer.content输入框内的记号（chip）触发符选中项在草稿里渲染成的样子
composer.readDraft / writeDraft方法，非界面读取输入框文字；往输入框写文字（含把记号写进草稿）
composer.attachments方法，非界面读取当前附件列表；把插件生成的文件写进附件区
中槽的宿主默认项只有「上下文用量」。插件可以隐藏它，也可以换成自己的（比如更细的用量显示）。替换后宿主的不显示；插件出错或卸载时宿主的回来。
宿主不再自带「提示词增强」。这个能力交给插件做（demo 场景 4）：插件在中槽放一个增强按钮，配上自己的撤销。宿主的增强按钮和撤销按钮移除。

触发符 已定 细节建议

  • 注册制（已定）：插件在清单里声明一个触发符号（如 #）。用户打出符号后，输入框上方弹出选择列表。
  • 样式固定、内容自定义（已定）：弹层的外观、交互（键盘上下选、回车确认）是宿主的；每一行里给什么图标、标题、描述、快捷记号，是插件的。
  • 数据可以远程拉（已定）：列表数据由插件取，包括去远程拉，避免主进程卡顿；宿主给加载态。
  • 选中后插入记号（已定）：选中项在草稿里是一个不可拆的记号（chip，如 【#数据1】），可以整体删除，不能从中间编辑。
  • 发送时解析（已定方向）：记号按结构化数据随消息一起走，发送前由插件把它展开成给 AI 的内容；记号长在界面上是什么和发给 AI 是什么，由插件说了算。
建议（未拍板）：两个插件注册同一个触发符号时，在安装时提示冲突，让用户当场选——与工具卡的认领规则一致。/ 和 @ 是宿主自己的，不对插件开放。

读写草稿与附件 建议

方向已定（插件要能读写输入框文字和附件），接口长什么样还没定：

  • composer.readDraft() — 拿到输入框当前文字（含记号的结构化表示）。
  • composer.writeDraft(text, options) — 往输入框写文字；支持在光标处插入、把记号写进去。是否要撤销（宿主记住写之前的样子）未定。
  • composer.getAttachments() — 拿到当前附件列表（名字、类型、大小、来源）。
  • composer.addAttachment(file) — 把插件生成的文件写进附件区，走宿主现有的附件路径（预览、随消息上传）。
写入附件涉及把文件落到宿主管的地方、随消息发给模型，权限名单独定；读草稿、写草稿、写附件预计各是一个权限。

本轮拍板 已定

问题结论
哪些控件固定附件、模式切换、权限切换、模型选择、发送 / 停止。插件碰不到
中槽插件能不能隐藏 / 替换宿主项能。宿主在中槽的默认项只有上下文用量，插件可隐藏或替换。目的就是让插件自己实现增强这类能力
宿主的提示词增强移除。按「增强不存在」设计，能力由插件实现（demo 场景 4）
触发符弹层样式宿主固定；列表项内容由插件给
列表数据来源插件自己取，可以远程拉，避免主进程卡顿
选中后插入什么不可拆的记号（chip）；发送时按结构化数据由插件解析
分支上旧的 ComposerControlSlot 原型废弃重做。旧 beforeSend 是把模型 + 上下文 + 增强整块移交给一个插件，与新边界（模型 / 发送固定、增强移除）冲突

和 #545 原文的关系 边界改口

#545 原文仅供参考，边界以本页为准。这是产品决定，不是实现漏项。

#545 原文的想象

  • 左右两排各留一个槽，插件随便加东西
  • 引用、补全、附件源、草稿改写是四个独立的点

本轮决定

  • 固定件收死：模式 / 权限 / 附件 / 模型 / 发送不许动
  • 中槽可以隐藏 / 替换宿主项——宿主增强移除，交给插件
  • 触发符 + 记号 + 解析连成一条线；草稿与附件读写是两组方法

还没定的事 未定

  • 中槽有多个插件时怎么排序（声明顺序？用户拖？按安装顺序？）。
  • 触发符的数据格式细节：选中项要带哪些字段、发送前在哪个环节解析、解析失败怎么办。
  • 触发符支持到什么程度：单字符还是多字符、能不能注册多个符号、和 / @ 的优先关系。
  • 两个插件抢同一个触发符的处理方式（目前建议安装时提示）。
  • writeDraft 要不要撤销；插件写入的文字用户能不能一键还原。
  • 附件方法的权限名、插件生成文件的存放位置与清理时机。
  • 记号被引用进历史消息后，重发 / 编辑消息时怎么处理。

明确不做 已定

  • 不让插件动五个固定件，也不在固定件中间插东西（左排固定件右边、模型选择左边这两个开口除外）。
  • 不让插件碰发送按钮的行为：拦截发送、改发送内容不属于输入区（解析记号是唯一出口）。
  • 不给整段对话历史——草稿和附件方法只针对当前输入框。
  • 不让插件在输入框里画任意自由界面：中槽 / 左槽是按钮级，弹层列表是固定 chrome。
  • 输入框上方的改动审阅卡、排队提示不在本目录。
